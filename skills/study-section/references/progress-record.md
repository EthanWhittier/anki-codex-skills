# Small, evidence-based progress records

Use one readable Markdown ledger per source unit plus the shared index. This is a bookmark and evidence record, not replacement chapter notes. Keep a stable unit ID and preserve an existing ledger's path across tasks.

## Fields

- Source title/edition/path or URL; exact section; printed/PDF page distinction when applicable.
- Parent chapter/track milestone, agreed depth/scope (master, read for context, reference/skip), optional/deferred topics, and session budget. Track only meaningful scope choices, not a row for every incidental fact.
- Reported reading position, active learning activity, and exact next action.
- Outcomes table: ID, capability, source/task, status, evidence.
- Brief dated evidence entries: actual task, a concise description of the learner's response, correctness/gap, and help used. Avoid storing full transcripts or answer keys in the learner-facing tracker.
- Later-check queue: agreed checks only, with outcome, concrete fresh task or task specification without its answer, earliest useful opportunity such as “next geology session after a gap,” and pending/completed/deferred result. Include checks covered by the accepted study plan; recommendations alone create no obligation. Consult the queue on resumption. Record whether notes, source, hints, or other assistance were used. Do not mark a same-session retry as a delayed check. Do not infer elapsed days without available date evidence.
- Anki candidates, chosen scope/budget if known, and verified created note IDs. Keep candidates, pending writes, and verified notes distinct. Record standing authorization only when explicitly given, with its limits.
- Optional reference notes or connections only when useful or requested.

## Outcome states

| Status | Meaning |
|---|---|
| Not assessed | No adequate learner evidence yet, even if the section was read. |
| Practicing | Instruction or attempts occurred; there is a remaining gap or relevant assistance was needed. |
| Demonstrated now | An adequate independent attempt on a stated task was observed in-session. Scope the claim to that task/capability. |
| Demonstrated later | An adequate fresh attempt was observed after a meaningful gap; this does not guarantee permanent mastery. |
| Deferred | The learner chose to set the outcome aside; preserve the reason if known. |

Record help separately: independent, hint, reference available, worked example/solution, or learner-reported evidence. When an answer used relevant help, do not label that attempt independent. An uncued fresh variation after teaching can support “demonstrated now,” with the recent instruction still noted. Immediate reproduction supports practice only.

## Unit status

- **In progress:** core outcomes lack adequate immediate evidence or have material unresolved gaps.
- **Core outcomes demonstrated; later check pending:** all agreed core outcomes have adequate immediate evidence; the learner may proceed.
- **Core outcomes checked later:** delayed evidence exists for the selected core outcomes. State any limits or untested areas.
- **Paused/advanced with gaps:** learner chose to move on; list unresolved/deferred outcomes explicitly.
- **Reading goal complete:** the agreed goal was context-only reading and the learner reports it finished; no mastery assessment is implied or required.

Optional goals do not silently become requirements. The learner can revise the core scope; record substantive revisions so a narrower scope is not mistaken for demonstration of the original goal. Remove later-check obligations for outcomes deliberately excluded from scope, preserving prior evidence and a brief scope-change note. Out-of-scope material is not review debt; do not keep resurfacing it as a gap or silently erase still-agreed pending checks.

## Update discipline

Read the current ledger before each write, including when resuming in another task. Merge new evidence rather than replacing the entire history from an old copy. Do not fabricate timestamps, study duration, attempts, reading completion, or card IDs. The initial seeded ledger must say no assessment has occurred.

At each checkpoint update only changed status, concise evidence, and next action. At session end preserve an unfinished prompt/part without revealing its solution. Update the index when the active unit changes. Show the learner where progress is saved on first use and after a change of location.
